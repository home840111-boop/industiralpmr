# Power Analyzer Report Redesign — Implementation Plan

## Goal
Redesign the existing Power Analyzer Report to be cleaner, less congested, and fully display phase data (R/S/T/SUM) for all power parameters with proper min/max/avg handling. Include graphical elements (charts, sparklines) and export to PDF/Excel.

---

Extract duplicated code from 3 files into one shared module:

## 4. UI Layout Design

### PhaseSummaryTable (shared by Power & Harmonics tabs)

**Key design: ONE unified table** instead of N separate MetricCards (eliminates congestion).

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ Parameter              │  Total (SUM)    │  Phase R        │  Phase S    ... │
│                        │Min   Avg   Max  │Min   Avg   Max  │Min   Avg  Max   │
├────────────────────────┼─────────────────┼─────────────────┼─────────────────┤
│ Voltage L-N (V)        │220   230   240  │221   231   239  │219  229  241    │
│ Line Voltage L-L (V)   │380   400   415  │382   401   417  │...             │
│ Current (A)            │ —   12.5  18.2  │ —    4.1   6.2  │ —   4.0  5.9   │
│ Active Power (kW)      │ —    8.2  12.1  │ —    2.7   4.1  │ —   2.6  3.9   │
│ Apparent Power (kVA)   │ —   10.1  15.3  │ —    3.4   5.1  │ ...            │
│ Reactive Power (kVAR)  │ —    2.1   4.5  │ —    0.8   1.5  │ ...            │
│ Power Factor           │0.85  0.92  0.98 │0.86  0.93  0.99 │...             │
│ Frequency (Hz)         │49.5  50.0  50.2 │  —    —     —   │ —   —    —     │
│ Neutral Current (A)    │ —    0.5   2.1  │  —    —     —   │ —   —    —     │
└──────────────────────────────────────────────────────────────────────────────┘
```

**Rules:**
- Metrics with `hasMin: true` (Voltage, Line Voltage, PF, Frequency, VTHD, ITHD) → 3 sub-columns (Min, Avg, Max)
- Metrics with `hasMin: false` (Current, kW, kVA, kVAR, Neutral) → 2 sub-columns (Avg, Max)
- Phases with `null` data are hidden (handles optional phase_values)
- Two header rows: phase group row + stat label row
- Highlight Avg column with `color="orange.500" fontWeight="600"`

```
┌─────────────────────────────────────────────────────────────────┐
│ [Phase: SUM ▼]                                                  │
├─────────────────────────────────────────────────────────────────┤
│ Hour         │ Voltage LN │ Voltage LL │ Current │ Power │ ... │
```

- Time formatted from `hour.from` → `hour.time` using `dayjs.unix().format("HH:mm")`
- Same hasMin logic for column visibility
- Sorted by `from` timestamp

## 6. Data Flow (unchanged)

The existing fetch logic in `index.tsx` stays the same:
- Single-day: fetch `reports/machines/{id}/daily/{date}` + `reports/machines/{id}/hourly/{date}` + accumulators
- Multi-day: range query with `orderByKey`, `startAt`, `endAt`
- Main meter: `simple_meter/daily` path with `mapSimpleMeterToPowerSchema`
- Transform via `transformDailyData()` (now from shared utility)

**Optional phase_values handling:**
- After fetch, check if `dayVal.phase_values` exists before transforming
- Pass `null` to tabs when absent
- Tabs show "No phase data available" message when `phase_values` is null
- PhaseSummaryTable hides columns where phase data is null
